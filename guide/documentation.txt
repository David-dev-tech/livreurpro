1. PRÉSENTATION DU PROJET
----------------------------------------------------------------

LivreurPro est une plateforme web de mise en relation entre
utilisateurs et livreurs au Cameroun (Douala). Elle permet à
un utilisateur de commander une livraison, de choisir un
livreur dans un catalogue, de suivre ses commandes sur une
carte interactive, et de payer à la livraison.

Trois types d'acteurs :
  - Utilisateur  : commande des livraisons
  - Livreur      : reçoit et effectue les livraisons
  - Administrateur : gère les utilisateurs, livreurs et livraisons


----------------------------------------------------------------
2. STACK TECHNIQUE
----------------------------------------------------------------

  - Frontend  : HTML5, CSS3 (variables CSS), JavaScript vanilla
  - Backend   : PHP 8+ (pas de framework)
  - Base de données : MySQL (PDO, charset utf8mb4)
  - Cartes    : Leaflet.js + OpenStreetMap / OSRM (itinéraires)
  - Emails    : PHPMailer (SMTP Gmail)
  - Animations 3D : Three.js (page d'accueil)
  - Icônes    : Font Awesome 6.4
  - Polices   : Google Fonts (Barlow, Barlow Condensed)

4. BASE DE DONNÉES
----------------------------------------------------------------

Nom de la base : livpro
Hôte           : localhost
Utilisateur    : root (à changer en production)
Mot de passe   : (vide en local, à configurer en production)

Tables principales :

  utilisateur
    id_user         VARCHAR  PK (ex: "id4aB2")
    mail            VARCHAR  UNIQUE
    nom_utilisateur VARCHAR  NULL
    date_creation   DATETIME

  livreur
    id_livreur      INT      PK AUTO_INCREMENT
    nom             VARCHAR
    prenom          VARCHAR
    age             INT      NULL
    sex             CHAR(1)
    numero          VARCHAR  UNIQUE
    mail            VARCHAR  NULL
    adresse         TEXT     NULL
    numero_cni      VARCHAR
    carte_grise     VARCHAR  NULL
    type_vehicule   ENUM('moto','tricycle','camionnette','camion')
    capacite_poids  INT      DEFAULT 500

  livraison
    id_livraison    INT      PK AUTO_INCREMENT
    id_user         VARCHAR  FK → utilisateur
    id_livreur      INT      FK → livreur
    adresse_ramassage TEXT   (format "lat,lng" ou texte)
    adresse_depot   TEXT
    distance        FLOAT
    prix            FLOAT
    poids           FLOAT
    type_vehicule   VARCHAR
    statut          ENUM('en_attente','acceptee','en_cours','terminee','annulee')
    date_creation   DATETIME

  note
    id_note         INT      PK AUTO_INCREMENT
    id_livreur      INT      FK → livreur
    note            TINYINT  (1–5)
    commentaire     TEXT     NULL

  commission
    id_commission   INT      PK AUTO_INCREMENT
    id_livraison    INT      FK → livraison
    montant         DECIMAL  (10% du prix de la livraison)

5. FLUX UTILISATEUR
----------------------------------------------------------------

  1. L'utilisateur saisit son email sur us_form.php
  2. models/inscrire_user.php :
       - Si email inconnu → INSERT dans `utilisateur`, génère un id_user (ex: "id4aB2")
       - Si email connu   → récupère l'id_user existant
       - Envoie l'id_user par email (PHPMailer / SMTP Gmail)
  3. L'utilisateur saisit son code sur us_otp.php
  4. models/verif_otp.php vérifie l'id_user en base, crée la session PHP
       ($_SESSION['id_user'], $_SESSION['mail'])
  5. Redirection vers us_catalogue.php
  6. L'utilisateur choisit un livreur, remplit le formulaire de livraison
       (adresses via carte Leaflet, poids, instructions)
  7. models/traiter_livraison.php :
       - INSERT dans `livraison` (statut = 'en_attente')
       - INSERT dans `commission` (10% du prix)
       - Envoie un email de notification au livreur
  8. L'utilisateur suit ses livraisons sur us_livraison.php
       (carte Leaflet avec itinéraire OSRM)


----------------------------------------------------------------
6. AUTHENTIFICATION ET SESSIONS
----------------------------------------------------------------

  - Pas de mot de passe : authentification par code OTP envoyé par email.
  - La session PHP stocke : id_user, mail.
  - Toutes les pages protégées vérifient isset($_SESSION['id_user'])
    et redirigent vers index.html si absent.
  - Déconnexion : supprimer la session via logout.php (à implémenter
    ou via session_destroy()).


----------------------------------------------------------------
7. CALCUL DU PRIX
----------------------------------------------------------------

  Prix = distance (km) × tarif_par_km (FCFA)

  Tarifs par type de véhicule :
    moto         : 300 FCFA/km
    tricycle     : 400 FCFA/km
    camionnette  : 500 FCFA/km
    camion       : 700 FCFA/km

  Commission plateforme : 10% du prix total
  (insérée dans la table `commission` à chaque livraison)


----------------------------------------------------------------
8. CARTE INTERACTIVE (Leaflet + OSRM)
----------------------------------------------------------------

  - Bibliothèque : Leaflet.js 1.9.4 (CDN)
  - Tuiles       : OpenStreetMap
  - Géocodage    : Nominatim via proxy.php (évite les CORS)
  - Itinéraires  : API OSRM publique (router.project-osrm.org)
  - Zone par défaut : Douala, Cameroun (lat: 4.0511, lng: 9.7679)
  - Les coordonnées sont stockées en base au format "lat,lng"

  proxy.php expose deux actions :
    GET proxy.php?action=search&q=Douala&limit=5
    GET proxy.php?action=reverse&lat=4.05&lon=9.77

  et le curseur natif est restauré (cursor: auto).


----------------------------------------------------------------
12. POINTS D'ATTENTION POUR LES DÉVELOPPEURS
----------------------------------------------------------------

  - config.php contient les credentials BDD en clair → à externaliser
    en production (variables d'environnement).

  - Le mot de passe SMTP Gmail est en clair dans inscrire_user.php
    et traiter_livraison.php → même remarque.

  - inscrire_livreur.php contient une fonction creerMailer() dupliquée
    de inscrire_user.php → à factoriser dans un fichier partagé.

  - ad_dashboard.php ne vérifie pas la session admin → à sécuriser.

  - Les pages livreur (liv_*.php) utilisent encore des données
    statiques (Jean Dupont, livraisons fictives) → à connecter à la BDD.

  - logout.php est référencé dans plusieurs fichiers mais n'existe
    pas encore dans le dépôt → à créer (session_destroy + redirect).

  - Le bouton logout a été retiré de toutes les vues (mai 2026).
    La déconnexion doit être gérée autrement (lien dans le menu,
    page dédiée, etc.).


----------------------------------------------------------------
13. LANCER LE PROJET EN LOCAL
----------------------------------------------------------------

  Prérequis :
    - PHP 8.0+
    - MySQL 5.7+ ou MariaDB
    - Serveur web (Apache/Nginx) ou PHP built-in server

  Étapes :
    1. Cloner le dépôt dans le dossier web (ex: htdocs/ ou www/)
    2. Créer la base de données "livpro" et importer le schéma SQL
       (voir guide/bd.txt)
    3. Vérifier config/config.php (hôte, nom BDD, user, password)
    4. Configurer le mot de passe App Gmail dans les models si besoin
    5. Ouvrir http://localhost/[dossier]/index.html
